# Угадай мелодию — V39

Корпоративная web-игра «Угадай мелодию» для проведения игры с ведущим на компьютере/телевизоре/проекторе и участниками на телефонах.

Постоянная ссылка:
https://goodspeed2k-ship-it.github.io/ugaday-melodiyu/

## Архитектура

- Frontend: один `index.html` + `version.json`.
- Backend: Supabase.
- Игроки подключаются с телефонов по коду комнаты/ссылке.
- Ведущий работает с компьютера и управляет игрой.
- Аудио проигрывается на устройстве ведущего.
- `STOP` определяется через серверный RPC Supabase `claim_buzz`, поэтому при почти одновременных нажатиях решение принимает сервер.

## Создание игры

При создании игры ведущий задаёт:

- название игры;
- количество команд: 2–6;
- названия команд;
- длительность раунда:
  - 15 + 15 минут;
  - 25 + 25 минут;
  - 35 + 35 минут.

В каждой команде может быть несколько участников. Каждый участник подключается со своего телефона.

## Игровое поле

Поле каждого раунда — 5 × 5:

- 5 категорий;
- стоимость вопросов: 100 / 200 / 300 / 400 / 500.

В игровом поле тип спецклетки не раскрывается заранее. Тип виден ведущему после открытия клетки.

## Раунды

### Раунд 1

Классическая игра с обычными песнями и возможностью использовать доступные механики.

### Раунд 2

Используются специальные типы клеток. В текущей заготовке предусмотрены:

- 🎒 Песня в мешке;
- 🔨 Аукцион;
- 🔄 АПОЖ;
- ⚡ Удвоение;
- 🖼️ По картинке.

После завершения второго раунда есть переход к финалу.

## Базовая механика обычной песни

1. Ведущий выбирает клетку.
2. Открывается текущая мелодия.
3. Ведущий запускает воспроизведение.
4. Участники могут нажимать `СТОП`.
5. Сервер определяет первую команду.
6. Ведущий видит, какая команда отвечает.
7. При правильном ответе команда получает стоимость клетки.
8. При обычной ошибке команда получает штраф −50% стоимости клетки.
9. После ошибки ведущий может открыть возможность ответа другим командам.

## 🎒 Песня в мешке

Механика реализована и протестирована.

Команда, выбравшая клетку, становится владельцем песни.

После открытия ведущий может:

- ✅ оставить песню себе;
- ↪ передать песню другой команде.

Если оставить песню себе:

- песня закрепляется за командой-владельцем;
- `СТОП` становится активным только у этой команды;
- после нажатия `СТОП` она становится отвечающей.

Если передать песню:

- `СТОП` становится активным только у выбранной команды;
- после её ошибки команда блокируется на эту песню;
- остальные команды получают возможность нажать `СТОП`.

## 🔄 АПОЖ

АПОЖ — реверс песни.

В подготовке для клетки доступны три варианта работы с реверсом:

- загрузить обычный MP3;
- загрузить отдельный реверс MP3;
- автоматически сделать реверс из обычного аудио.

Автоматический реверс выполняется непосредственно в браузере через Web Audio API, после чего перевёрнутый файл сохраняется в Supabase Storage.

Для клетки типа `АПОЖ` воспроизводится именно `reverse_audio_url`.

Механика АПОЖ была протестирована и подтверждена как рабочая.

## ⚡ Удвоение

Для клетки типа `Удвоение`:

- стоимость клетки остаётся исходной для отображения на поле;
- при правильном ответе команда получает ×2 от номинала;
- при ошибке штраф остаётся обычным −50% от номинала.

Примеры:

- 100 → +200 / −50;
- 300 → +600 / −150;
- 500 → +1000 / −250.

На экране ведущего и игрока отображается подсказка, что вопрос является удвоением.

## 🔨 Аукцион

Тип клетки и базовая механика выбора победителя уже присутствуют в интерфейсе.

Текущая реализация V39 не является полноценным отдельным интерфейсом аукционных ставок: ведущий после устной торговли вручную выбирает команду, которой достаётся право ответа.

Полноценный аукцион со ставками и отдельным интерфейсом запланирован на следующий этап.

## 🖼️ По картинке

Для клетки типа «По картинке» можно загрузить изображение.

После открытия ведущий видит изображение-загадку. Механика начисления и специальная логика награды пока не доведены до финального варианта.

## 🧪 Тест «Песни в мешке»

В ведущем есть отдельная кнопка `🧪 Тест мешка`.

Это локальный тестовый стенд, который не изменяет текущую игру и базу данных.

В нём можно отдельно проверить:

- оставить песню владельцу;
- передать другой команде;
- нажатие `СТОП`;
- правильный ответ;
- ошибку и блокировку команды;
- повторный доступ остальных команд после ошибки;
- перезапуск сценария.

## Подготовка вопросов

В режиме подготовки:

- поле также 5 × 5;
- выбор клетки открывает центрированный редактор;
- можно указать «исполнитель — название»;
- можно указать правильный ответ;
- можно выбрать тип клетки;
- можно загрузить обычный MP3;
- можно загрузить реверс MP3;
- можно автоматически создать реверс;
- можно загрузить изображение;
- есть предпрослушивание аудио до 10 секунд;
- состояние загрузки/готовности показывается в редакторе.

## Таймеры

Для раундов доступны три пресета:

- 15 + 15 минут;
- 25 + 25 минут;
- 35 + 35 минут.

Ведущий видит оставшееся время раунда.

При завершении времени текущий раунд переводится в состояние завершённого.

## Финал — отложенная механика

Финальный раунд в V39 ещё не реализован как полноценная игровая механика.

Запланирован отдельный режим под рабочим названием:

**«Финальное дело» / «Песенный детектив»**

Идея:

1. Команды делают тайные ставки.
2. Загадка одной песни раскрывается поэтапно.
3. Подсказки могут включать ассоциации/изображения, факты и короткий музыкальный фрагмент.
4. Чем раньше команда отвечает, тем выше потенциальный выигрыш.
5. Вместо `СТОП` команды вводят ответ на телефонах.
6. Ведущий раскрывает правильный ответ и фиксирует результаты.

Эту механику сознательно отложили до этапа разработки финала, после тестирования основной игры.

## Технические заметки

- Не использовать service-role/secret key в браузерном коде.
- Текущая игра использует publishable key Supabase.
- Все игровые изменения идут через клиентскую логику и существующие SQL RPC/табличные поля.
- Аудио и изображения хранятся в Supabase Storage.
